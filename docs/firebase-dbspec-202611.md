# PointMarker - Firebaseデータ構造仕様書（共有プロジェクト版）

## 概要

PointMarkerアプリケーションは、Firebase Firestoreを使用してハイキングマップ画像上のポイント、ルート、スポット、エリアデータを永続化します。本仕様書では、**共有プロジェクト**として、認証済みユーザー全員が全プロジェクトを読み書き可能なデータ構造、セキュリティルール、データの流れについて説明します。

**【重要な変更点】**
- ユーザーID階層を削除し、`projects/{projectId}/` に直接保存
- 認証済みユーザーなら誰でも全プロジェクトを読み書き可能
- PNG画像ファイル名がプロジェクトキー（画像はメンバーにのみ配布。Firestoreへのアクセス自体は制限しない）

## 2. Firestoreデータ構造

### 2.1 コレクション階層

```
projects/{projectId}/
  ├── (プロジェクトメタデータ)
  ├── points/{pointId}/
  │   └── (ポイントデータ)
  ├── routes/{routeId}/
  │   └── (ルートデータ)
  ├── spots/{spotId}/
  │   └── (スポットデータ)
  └── areas/{areaId}/
      └── (エリアデータ)
```

**階層構造の特徴:**
- **共有プロジェクト**: ユーザーID階層なし、`projects/{projectId}` に直接保存
- **全員アクセス可能**: 認証済みユーザーなら誰でも全プロジェクトを読み書き可能
- **画像ファイル名がキー**: プロジェクトID = 画像ファイル名（拡張子なし）
- **画像の配布**: PNG画像ファイルはメンバーにのみ配布（Firestoreへのアクセス自体は制限しない）
- **サブコレクション**: ポイント、ルート、スポット、エリアはプロジェクトのサブコレクション
- **ドキュメントID**: `pointId`・`routeId`・`spotId`・`areaId` はFirestoreの自動生成ID

---

### 2.2 ドキュメント構造

#### 2.2.1 プロジェクトメタデータ

**コレクションパス**: `projects/{projectId}`

| フィールド名 | 型 | 必須 | 説明 | 例 |
|------------|---|------|------|---|
| `projectName` | string | ✅ | プロジェクト名 | "箕面大滝" |
| `imageName` | string | ✅ | 画像ファイル名 | "箕面大滝.png" |
| `imageWidth` | number | ✅ | 画像の幅（ピクセル） | 1920 |
| `imageHeight` | number | ✅ | 画像の高さ（ピクセル） | 1080 |
| `createdBy` | string | ✅ | 作成者のユーザーID | "user_abc123..." |
| `createdAt` | timestamp | ✅ | 作成日時（サーバータイムスタンプ） | 2025-11-16T10:00:00Z |
| `updatedAt` | timestamp | ✅ | 更新日時（サーバータイムスタンプ） | 2025-11-16T12:30:00Z |
| `lastAccessedAt` | timestamp | ✅ | 最終保存操作日時（読み込み時は更新しない） | 2025-11-16T12:30:00Z |
| `lastUpdatedBy` | string | ✅ | 最終更新者のユーザーID | "user_xyz789..." |
| `pointCount` | number | ✅ | ポイント数（集計用） | 15 |
| `routeCount` | number | ✅ | ルート数（集計用） | 1 |
| `spotCount` | number | ✅ | スポット数（集計用） | 8 |
| `areaCount` | number | ⚪ | エリア数（集計用。旧版で作成したプロジェクトには無い場合がある） | 2 |

**プロジェクトID**: 画像ファイル名（拡張子なし）を使用

**作成・更新タイミング**:
- 作成: 初回保存時に `commitSync()` で作成
- 更新: データ保存時に `commitSync()` でタイムスタンプ更新
- カウンター: ポイント・ルート・スポット・エリアの追加/削除時に自動更新

---

#### 2.2.2 ポイントデータ

**コレクションパス**: `projects/{projectId}/points/{pointId}`

| フィールド名 | 型 | 必須 | 説明 | 例 |
|------------|---|------|------|---|
| `id` | string | ✅ | ポイントID（X-nn形式） | "A-01", "B-15" |
| `x` | number | ✅ | X座標（画像座標系） | 512 |
| `y` | number | ✅ | Y座標（画像座標系） | 768 |
| `index` | number | ✅ | 取得時の並び順キー（現在の保存処理では常に0。無いドキュメントは取得されない） | 0 |
| `isMarker` | boolean | ⚪ | マーカーフラグ（保存時は常にfalse、読み込み時は未使用） | false |
| `createdAt` | timestamp | ✅ | 作成日時（サーバータイムスタンプ） | 2025-11-16T10:00:00Z |
| `updatedAt` | timestamp | ✅ | 更新日時（サーバータイムスタンプ） | 2025-11-16T12:30:00Z |

**ポイントID形式**: 正規表現 `/^[A-Z]-\d{2}$/`（大文字1文字 + ハイフン + 2桁数字）

**座標系**: 画像座標系（PNG画像の実ピクセル座標）
- 保存時: キャンバス座標 → 画像座標に変換
- 読み込み時: 画像座標 → キャンバス座標に変換

**照合・重複チェック**:
- 読み込み・保存済みの項目はドキュメントIDで照合（IDを変更しても同じドキュメントを更新）
- それ以外はポイントID（`id`フィールド）で照合。保存後にIDが重複する場合は保存しない

**空白ID処理**:
- 保存時: 空白ID（`id.trim() === ''`）のポイントはスキップ
- 読み込み時: 空白IDのポイントはスキップ

---

#### 2.2.3 ルートデータ

**コレクションパス**: `projects/{projectId}/routes/{routeId}`

| フィールド名 | 型 | 必須 | 説明 | 例 |
|------------|---|------|------|---|
| `routeName` | string | ✅ | ルート名 | "A-01 ～ B-05" |
| `startPoint` | string | ✅ | 開始ポイント（ポイントIDまたはスポット名） | "A-01" |
| `endPoint` | string | ✅ | 終了ポイント（ポイントIDまたはスポット名） | "B-05" |
| `waypoints` | array | ✅ | 中間点の配列（画像座標系） | `[{x: 100, y: 200}, {x: 150, y: 250}]` |
| `waypointCount` | number | ✅ | 中間点の数（集計用） | 2 |
| `description` | string | ⚪ | ルートの説明（画面では編集しない。更新時は既存値を保持し、JSONに含まれる場合のみその値で更新） | "" |
| `createdAt` | timestamp | ✅ | 作成日時（サーバータイムスタンプ） | 2025-11-16T10:00:00Z |
| `updatedAt` | timestamp | ✅ | 更新日時（サーバータイムスタンプ） | 2025-11-16T12:30:00Z |

**中間点（waypoints）の構造**:
```javascript
{
  x: number,  // X座標（画像座標系）
  y: number   // Y座標（画像座標系）
}
```

**ルート名**: 追加時は `ルートN`。開始・終了ポイントが揃うと `{startPoint} ～ {endPoint}` の形式で自動生成

**照合・重複チェック**:
- 読み込み・保存済みの項目はドキュメントIDで照合
- それ以外は開始ポイント（`startPoint`）と終了ポイント（`endPoint`）の両方で照合。保存後に重複する場合は保存しない
- 開始・終了ポイントとも未設定のルートは、内容全体が一致する場合のみ同一とみなす

**複数ルート**: 1プロジェクトに複数ルートを保存・読み込み可能。開始・終了ポイントが未設定のルートも空文字列で保存される

---

#### 2.2.4 スポットデータ

**コレクションパス**: `projects/{projectId}/spots/{spotId}`

| フィールド名 | 型 | 必須 | 説明 | 例 |
|------------|---|------|------|---|
| `name` | string | ✅ | スポット名 | "箕面大滝", "展望台" |
| `x` | number | ✅ | X座標（画像座標系） | 512 |
| `y` | number | ✅ | Y座標（画像座標系） | 768 |
| `index` | number | ✅ | 取得時の並び順キー（現在の保存処理では常に0。無いドキュメントは取得されない） | 0 |
| `description` | string | ⚪ | スポットの説明 | "" |
| `category` | string | ⚪ | カテゴリ | "" |
| `createdAt` | timestamp | ✅ | 作成日時（サーバータイムスタンプ） | 2025-11-16T10:00:00Z |
| `updatedAt` | timestamp | ✅ | 更新日時（サーバータイムスタンプ） | 2025-11-16T12:30:00Z |

**スポット名**: 任意の文字列（ポイントIDのような形式制限なし）

**座標系**: 画像座標系（PNG画像の実ピクセル座標）
- 保存時: キャンバス座標 → 画像座標に変換
- 読み込み時: 画像座標 → キャンバス座標に変換

**照合・重複チェック**:
- 読み込み・保存済みの項目はドキュメントIDで照合（改名・移動しても同じドキュメントを更新）
- それ以外は、スポット名（`name`）が一致し、座標の差が丸め誤差の範囲内の場合のみ同一とみなす
- 離れた場所の同名スポット、同じ座標の別名スポットは、それぞれ別のドキュメント
- `description` と `category` は更新時に既存値を保持

**空白名処理**:
- 保存時: 空白名（`name.trim() === ''`）のスポットはスキップ
- 読み込み時: 空白名のスポットはスキップ

---

#### 2.2.5 エリアデータ

**コレクションパス**: `projects/{projectId}/areas/{areaId}`

| フィールド名 | 型 | 必須 | 説明 | 例 |
|------------|---|------|------|---|
| `areaName` | string | ✅ | エリア名 | "崩落箇所" |
| `vertices` | array | ✅ | 頂点の配列（画像座標系、多角形の接続順） | `[{x: 100, y: 100}, {x: 200, y: 150}, {x: 150, y: 200}]` |
| `vertexCount` | number | ✅ | 頂点の数（集計用） | 3 |
| `createdAt` | timestamp | ✅ | 作成日時（サーバータイムスタンプ）。取得時の並び順キー | 2026-11-22T10:00:00Z |
| `updatedAt` | timestamp | ✅ | 更新日時（サーバータイムスタンプ） | 2026-11-22T12:30:00Z |

**頂点（vertices）の構造**:
```javascript
{
  x: number,  // X座標（画像座標系）
  y: number   // Y座標（画像座標系）
}
```

**照合・重複チェック**:
- 読み込み・保存済みの項目はドキュメントIDで照合
- それ以外はエリア名（`areaName`）で照合。保存後に名前が重複する場合は保存しない

**空白名処理**: 保存時に空白名のエリアはスキップ。頂点数による除外はしない

## 3. データ操作フロー

### 3.1 保存フロー（saveAllToFirebase）

```
1. バリデーション
   ├── Firebase接続確認
   ├── 画像読み込み確認
   └── 読み込み・保存の処理中でないことの確認

2. 画面データの写し取り（captureLocal）
   ├── 空白ID・空白名スキップ
   └── キャンバス座標 → 画像座標変換

3. Firestoreの現状取得
   ├── プロジェクトメタデータ（他の保存を検出するため最初に取得）
   └── ポイント → ルート → スポット → エリア

4. 保存内容の決定（planSync）
   ├── ドキュメントIDで照合
   ├── IDで照合できない項目はキーで照合
   ├── 画面で未変更の項目は書き込まない
   └── 基準情報のあるドキュメントに限り削除対象

5. 反映前の検査
   ├── キーの重複 → 中止
   └── 未読・他で変更されたデータの上書き/削除 → 確認ダイアログ

6. 一括反映（commitSync: 1トランザクション）
   ├── メタデータの updatedAt と更新・削除対象の内容を再検査（不一致なら中止）
   ├── 追加・更新・削除
   └── メタデータ・カウンター更新

7. 基準情報の更新（成功時のみ）

8. 結果表示
   └── 保存・削除・残したデータの件数メッセージ
```

**重要な仕様**:
- **基準情報**: 読み込み・保存に成功した時点の「ドキュメントID・画面側の内容・Firestore側の内容」をタブのメモリに保持（Firestoreには保存しない。ページの再読み込みで消える）
- **削除の範囲**: 基準情報の無いドキュメントは削除しない
- **原子性**: 保存は全件成功か、全件変更なし
- **リサイズ**: 座標の再計算は画面での変更として扱わない（`keepUnchangedAcross()`）
- **保存ボタン以外の書き込み**: エリア名の変更時のみ `updateAreaToFirebase()` で名前を即時更新（基準情報があり、他での変更・同名のエリアが無い場合に限る）
- **検出の限界**: メタデータを更新しない方法（Firebase Console等）で保存中に追加されたデータとの重複は検出できない
- **座標変換**: すべての座標は画像座標系の整数に丸めて保存
- **空白データ除外**: 空白ID/名のデータは保存しない

---

### 3.2 読み込みフロー（loadFromFirebase）

```
1. バリデーション
   ├── Firebase接続確認
   ├── 画像読み込み確認
   └── プロジェクト存在確認

2. 既存データクリア確認
   ├── 既存データ有無チェック（ポイント・スポット・選択中ルートの中間点）
   ├── 該当時のみユーザー確認ダイアログ
   └── 4種別の取得がすべて成功した後に、画面のデータと基準情報をクリア

3. ポイント読み込み（4種別の取得をすべて終えてから変換）
   ├── Firestoreから取得（getPoints）
   ├── 空白IDスキップ
   ├── 画像座標 → キャンバス座標変換
   └── PointManager追加

4. ルート読み込み
   ├── Firestoreから取得（getRoutes）
   ├── 全ルートについてドキュメントIDを保持
   ├── 開始・終了ポイント設定
   ├── 中間点の座標変換（画像 → キャンバス）
   └── RouteManager追加

5. スポット読み込み
   ├── Firestoreから取得（getSpots）
   ├── 空白名スキップ
   ├── 画像座標 → キャンバス座標変換
   └── SpotManager追加

6. エリア読み込み
   ├── Firestoreから取得（getAreas）
   ├── 頂点の座標変換（画像 → キャンバス）
   └── AreaManager追加

7. UI更新
   ├── キャンバス再描画
   ├── ポップアップ再生成
   └── 読み込み件数メッセージ
```

**重要な仕様**:
- **上書き確認**: ポイント・スポット・選択中ルートの中間点がある場合のみ確認ダイアログ表示
- **座標変換**: 保存時と逆の変換で元の表示位置を復元
- **複数ルート・エリア**: 保存されている全件を読み込み
- **基準情報**: 画面に読み込んだ各項目のドキュメントIDと内容を記録（読み飛ばした空白ID/名のデータは記録しないため、保存時に削除されない）

## 4. セキュリティルール

### 4.1 Firestoreセキュリティルール（共有プロジェクト版）

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // 共有プロジェクト: 認証済みユーザーなら誰でも読み書き可能
    match /projects/{projectId} {
      // 認証必須（匿名認証でもOK）
      allow read, write: if request.auth != null;

      // ポイント・ルート・スポットのサブコレクション
      match /{document=**} {
        allow read, write: if request.auth != null;
      }
    }
  }
}
```

**ルールの特徴**:
- **認証必須**: すべての操作で認証が必須（`request.auth != null`）
- **全員アクセス可能**: 認証済みユーザーなら誰でも全プロジェクトを読み書き可能
- **再帰的ルール**: `{document=**}` でサブコレクションすべて（`areas` を含む）に適用
- **画像の配布**: PNG画像ファイルは外部公開せず、メンバーにのみ配布（Firestoreへのアクセス自体は制限しない）

**現行ルールを許容する理由**:
- 本アプリの保存データは画像内座標と名称などであり、画像ファイル名や格納データを取得されてもPNG画像ファイルなしでは実質的に意味がない
- 改竄された場合も、別に保管しているバックアップから復旧できる

## 5. データ同期とキャッシング

### 5.1 キャッシュ（永続化は無効）

**Firestore設定**（FirebaseClient.js:31-35）:
- `enablePersistence()` は呼び出さず、メモリキャッシュのみで動作
- 無効化の理由: 古いSDKバージョンのデータとの互換性問題を避けるため
- ページを再読み込みするとキャッシュは失われる

---

### 5.2 リアルタイムリスナー

**実装状況**: FirestoreDataManagerにリスナー機能実装済み（現在未使用）

**利用可能なメソッド**:

- `onRoutesSnapshot(projectId, callback)`: ルート変更監視
- `onSpotsSnapshot(projectId, callback)`: スポット変更監視

**将来の拡張**:
- リアルタイム同期機能
- 複数デバイス間のデータ共有
- 変更通知機能

## 6. エラーハンドリング

### 6.1 重複検出

**保存処理の重複検出**（SyncPlanner）:

| データ種別 | 重複判定条件 | 重複時の処理 |
|-----------|------------|---------|
| ポイント | `id` が一致 | 保存全体を中止 |
| ルート | `startPoint` と `endPoint` が両方一致 | 保存全体を中止 |
| スポット | 重複判定しない（同名を許容） | - |
| エリア | `areaName` が一致 | 保存全体を中止 |

**個別追加API**（FirestoreDataManagerの `addPoint()` 等。現在の保存処理では未使用）が重複時に返す値:
```javascript
{
  status: 'duplicate',
  type: 'point' | 'route' | 'spot' | 'area',
  existing: { /* 既存データ */ },
  attempted: { /* 追加しようとしたデータ */ }
}
```

**アプリ側の処理**（FirebaseSyncManager）:
- 重複した項目名をOKボタン付きメッセージで表示
- `DuplicateDialog` は使用しない

---

### 6.2 エラーメッセージ

**主なエラーケース**:

| エラー | 原因 | メッセージ |
|-------|------|-----------|
| 接続失敗 | Firebase初期化・匿名認証の失敗 | "接続失敗: {詳細}"（認証状態パネル） |
| Firebase未接続 | 接続が無い状態で読み込み処理を実行 | "Firebase接続が利用できません" |
| 画像未読み込み | 画像選択前に読み込み処理を実行 | "先に画像を読み込んでください" |
| 保存の前提不足 | 接続または画像が無い状態で保存処理を実行 | "Firebase接続または画像がありません" |
| プロジェクト不在 | 保存履歴なし | "画像 xxx に対するデータがありません" |
| 処理中 | 読み込み・保存の処理中に実行 | "データベースの処理中です。完了までお待ちください" |
| 重複 | 保存後に一意キーが重複する | "次の項目が画面内またはデータベース上の別のデータと重複するため、保存しませんでした。…" |
| 保存の取消 | 上書き・削除の確認でキャンセル | "保存をキャンセルしました。データベースは変更していません" |
| 保存中の競合 | 照合後に他で変更された | "保存中に他で変更があったため中止しました（データベースは変更していません）。もう一度「保存」を実行してください" |
| 保存失敗 | 読み取り・トランザクションの失敗 | "保存中にエラーが発生しました。画面のデータは残っています。もう一度「保存」を実行してください" |
| 権限エラー | セキュリティルール違反 | "Missing or insufficient permissions" |
| CORS エラー | file:// プロトコルでアクセス | "CORS policy" |

## 9. 座標系の管理

### 9.1 座標系の種類

PointMarkerでは5種類の座標系を使用しますが、Firestoreに保存する座標は**画像座標系**のみです。

| 座標系 | 説明 | Firestore保存 |
|-------|------|-------------|
| 画像座標系 | PNG画像の実ピクセル座標 | ✅ **保存する** |
| キャンバス座標系 | 表示用スケール座標 | ❌ 保存しない |
| スクリーン座標系 | ブラウザ内絶対位置 | ❌ 保存しない |
| マウス座標系 | イベントから得られる座標 | ❌ 保存しない |
| ズーム・パン座標系 | 変換行列適用後の座標 | ❌ 保存しない |

---

### 9.2 座標変換

**保存時** (キャンバス座標 → 画像座標):
```javascript
const imageCoords = CoordinateUtils.canvasToImage(
    point.x, point.y,
    canvasWidth, canvasHeight,
    imageWidth, imageHeight
);
```

**読み込み時** (画像座標 → キャンバス座標):
```javascript
const canvasCoords = CoordinateUtils.imageToCanvas(
    point.x, point.y,
    canvasWidth, canvasHeight,
    imageWidth, imageHeight
);
```

**重要**: 画像座標系で保存することで、異なる画面サイズやズーム倍率でも正確に元の位置を復元可能

## 10. まとめ

### 10.1 データ構造の特徴

- ✅ **共有プロジェクト**: ユーザーID階層なし、`projects/{projectId}` に直接保存
- ✅ **全員編集可能**: 認証済みユーザーなら誰でも全プロジェクトを読み書き可能
- ✅ **画像ファイル名がキー**: プロジェクトID = PNG画像ファイル名（拡張子なし）
- ✅ **アクセス制御**: 認証のみ（画像の配布先の限定は、Firestoreへのアクセス制御ではない）
- ✅ **座標の可逆性**: 画像座標系で保存により復元が可能（整数への丸め誤差あり）
- ✅ **重複検出**: データ種別ごとに適切な重複判定
- ✅ **共同編集**: 複数ユーザーが編集可能（別々の項目の変更は両立。同じ項目の変更は確認のうえ後から保存した内容で上書き）
- ✅ **作成者記録**: `createdBy`/`lastUpdatedBy`フィールドで誰が作成・更新したかを記録
